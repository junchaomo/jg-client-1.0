## 1. 背景与目标

在中枢内新增「地下管网」功能模块，接入既有管线普查成果，在三维场景中查看管点、管线，并提供主流管网模块应有的查询、统计与专业分析能力。

目标边界（本轮已确认）：

- **数据来源**：已有标准普查成果（SHP / GDB / GeoJSON，点-线拓扑表，含管径、材质、埋深、高程、流向、权属等字段）。
- **场景底座**：一期为纯管线空场景，不叠加地形 DEM、影像底图或倾斜摄影 / BIM / 点云；地形与实景三维接口预留，二期接入。
- **功能范围**：含数据管理全套（入库接边、拓扑检查、属性维护、统计导出）+ 主流专业分析。
- **部署约束**：Electron 桌面端、内网离线为主；三维引擎与静态资源必须可随包离线分发。

## 3. 功能范围（对照国标与主流产品）

### 3.1 三维浏览

- 场景交互：放大 / 缩小 / 平移 / 漫游 / 复位 / 视角（顶视 / 侧视 / 剖切视角）/ 全屏。
- 图层控制：按管线中类（供水、排水、燃气、热力、电力、通信、工业、综合管廊、其他）显隐、按权属 / 道路 / 年代过滤。
- 地上地下：地表参考面开关、半透明地表模式、竖向剖切 / 开挖视口、垂向 exaggeration 调整。
- 符号化：管段按管径 / 类型着色，管点按特征 / 附属物分类符号；选中高亮。
- 场景输出：视角快照截图（二期）；漫游录制（二期）。

### 3.2 查询与定位

- 图查属性：拾取管点 / 管段，右侧属性面板展示全字段。
- 属性查图：按点号 / 段号 / 道路 / 权属 / 材质 / 管径 / 年代条件检索，列表命中并在场景定位高亮。
- 空间查询：框选 / 圈选范围内要素。
- 双向联动：场景选中 ↔ 属性表 / 列表高亮联动。

### 3.3 统计

- 按管线中类、材质、道路、权属、年代统计管线长度、管点数量、管段数量。
- 图表展示（复用现有 echarts 依赖）；统计结果可导出报表。

### 3.4 专业分析

| 分析项 | 输入 | 输出 | 计算归属（建议） |
| --- | --- | --- | --- |
| 横断面分析 | 剖切线 / 拾取管线 | 剖面线与各管段高程、管径、净距关系图 | 后端几何批量 + 前端剖面绘制 |
| 纵断面分析 | 选定管段 / 管线走向 | 沿程埋深、高程坡度曲线 | 后端几何 + 前端曲线 |
| 连通分析 | 选中管点 / 管段，方向 | 连通的上下游节点与管段集合，高亮 | 后端拓扑图算法 |
| 爆管分析 | 爆点（节点 / 管段） | 上游应关阀门、受影响管段与用户 / 设施清单 | 后端拓扑追溯（有压 / 自流分规则） |
| 水平净距 |  tolerance 阈值 | 并行 / 交叉管段水平间距不足清单 | 后端几何（shapely） |
| 垂直净距 / 碰撞 |  tolerance 阈值 | 上下交叉竖向净距不足、碰撞清单 | 后端几何 |
| 覆土埋深分析 | 全域 / 范围 | 各管段埋深分级（浅 / 中 / 深）与异常清单 | 后端几何 + 属性计算 |
| 流向分析 | 选中管线 | 流向箭头 / 流向追溯，与高程差校核 | 后端拓扑 + 前端箭头渲染 |
| 最短路径 | 起终点 | 两节点间拓扑路径与长度 | 后端图算法（Dijkstra） |
| 缓冲区分析 | 要素 / 半径 | 缓冲范围内相交的其他管线 / 设施 | 后端几何 |
| 开挖分析（土方量） | 开挖范围线 / 深度 | 范围内管线数量、类型、估算土方量 | 后端几何（二期） |

### 3.5 数据管理

- 入库接边：导入 SHP / GDB / GeoJSON，字段映射、坐标与高程基准登记、批量落库；重复入库按点号 / 段号判重。
- 拓扑检查：孤立点、悬挂线（端点未接其他管段）、重复管段 / 重复管点、缺坐标、缺高程、流向与高程矛盾、未定义材质 / 管径等；生成问题清单，可定位回看。
- 属性维护：管点 / 管段属性编辑，变更留审计（操作人、前后值、时间）。
- 历史版本：数据集版本与回滚（二期，沿用现有 file_versions 思路）。
- 导出制图：导出 SHP / GeoJSON；导出剖面图、统计报表。

### 3.6 数据质量与标准对齐

- 管线中类：供水、排水、燃气、热力、电力、通信、工业、综合管廊（沟）、其他。
- 埋深语义区分：有压管为覆土深度（管外顶至地面）；自流管为内底埋深（管内底至地面）；电缆直埋 / 管埋为覆土深度；方沟为内底埋深。
- 高程关系：管内 / 管顶高程 = 地面高程 − 埋深；入库时按埋深语义校核一致性。

## 4. 关键决策与选型对比

### 4.0 开源技术栈与许可证合规（硬约束）

本模块全部基于开源组件构建，**不引入商业 GIS SDK 与专有许可**（排除 SuperMap iObjects、MapGIS 商业平台、Mapbox GL JS v2 专有版本等）。选用组件均为 OSI 认可的宽松许可；Copyleft 项目仅作概念参照，不链接其代码，避免 GPL 传染自有模块。

| 层 | 候选组件 | 许可证 | 用途 | 一期取舍 |
| --- | --- | --- | --- | --- |
| 三维渲染 | Three.js | MIT | 管线 / 井体三维符号、剖切、拾取高亮、场景交互 | **一期选用** |
| 三维渲染（备选） | CesiumJS | Apache-2.0 | 真三维地球、地形 / 影像 / 3D Tiles | 二期上实景三维时评估；不用 Cesium ion 托管则无外部付费依赖 |
| 二维地图（备选） | OpenLayers | BSD-2-Clause | 任意坐标系（proj4）、OGC WMS/WMTS/WFS、矢量图层 | 二期二三维一体 / 叠加 OGC 底图时评估；适配地方独立坐标系优于 MapLibre |
| 二维地图（备选） | MapLibre GL JS | BSD-3-Clause | WebGL 矢量瓦片、风格化地图 | 投影以 Web Mercator 为主，地方独立坐标系不适配，仅备选 |
| 客户端几何 | Turf.js | MIT | 缓冲、量算、叠加等轻量前端计算 | 按需引入；批量几何仍以后端 shapely 为准 |
| 拓扑示意 | Cytoscape.js | MIT | 连通 / 追溯结果的二维网络关系示意 | 现有仓库已装，可直接复用 |
| 图表 | ECharts | Apache-2.0 | 统计图表 | 现有仓库已装 |
| 服务端几何 / 解析 | shapely / pyogrio / numpy | BSD-3 / MIT / BSD-3 | 矢量读取、净距、碰撞、覆土、剖面、缓冲 | 现有 vendor/gis 已具备 |
| 图算法 | 自研（Node / Python） | — | 连通、爆管追溯、最短路径、流向 | 参照 Utility Network 概念，不依赖第三方网络分析 SDK |
| 存储 | node:sqlite（现有底座） | 内置 | 一期本地持久化 | 沿用；二期多用户 / 海量再评估 PostGIS（PostgreSQL License，开源） |

**成熟开源管网平台适配性评估（为何不直接套一套开源管网系统二次开发）：**

| 项目 | 定位 / 技术栈 | 许可证 | 适配结论 |
| --- | --- | --- | --- |
| Giswater | 供排水 / 雨洪全周期管理，Python + PL/SQL + 空间数据库，集成 EPANET / SWMM，QGIS 生态桌面应用 | GPL-3.0 | 偏水务专业二维桌面，依赖 PostGIS 与水力模型；非综合管网三维 Web 场景，难以嵌入现有 Electron 中枢的会话 / 权限 / 审计 / 应用市场体系。仅参照其资产管理、剖面、数据质检与最小割思路 |
| QGIS Network Studio 插件 | 工具网络建模与追溯（连通 / 上下游 / 隔离关阀 / 最短路径 / 环路 / 子网络），概念仿 ArcGIS Utility Network，支持 GeoPackage / SpatiaLite / PostGIS | GPL-3.0（插件） | QGIS 桌面插件，非可内嵌 Web 运行时；其网络建模、终端 / 连通规则、追溯与校验（悬挂 / 间隙 / 孤岛）概念可作为后端拓扑设计参照，不链接其代码 |
| 国内开源综合三维管网 Web 系统 | 调研未发现可直接内嵌、许可证清晰、社区活跃的成熟底座；市面三维管线产品（StampGIS / MapGIS / SuperMap / iPipeModeler）为商业或基础版免费、API 授权收费 | 商业 / 专有 | 不作为底座 |

**合规要点：**

- MIT / Apache-2.0 / BSD 系列为宽松许可，可随 Electron 客户端闭源分发；保留各组件 LICENSE 与版权声明即可。
- Giswater、Network Studio 为 GPL-3.0：仅借鉴其功能概念与数据建模思路，**不复制、不链接其源码**；自有模块不衍生 GPL 义务。
- CesiumJS 本体 Apache-2.0 免费商用；Cesium ion 托管地形 / 影像为可选付费服务，一期纯空场景不使用 ion，无外部账号与费用。

### 4.1 三维引擎（已实测离线体积，2026-11-18，npmmirror 镜像）

| 维度 | Three.js 0.187.0 | CesiumJS 1.147.0 |
| --- | --- | --- |
| 整包解包体积 | 20.1 MB（含 examples / docs，生产裁剪后很小） | 76.5 MB |
| 生产核心 | `build/three.module.js` 643 KB（gzip ≈ 170 KB）；addons 按需引入 | `Build/Cesium` 21.79 MB，另需 Workers / Assets / Widgets / ThirdParty 静态目录 |
| 额外静态资产 | 无强制 worker / asset 目录 | 需配置 `CESIUM_BASE_URL`，worker 脚本与静态资源随包分发；mime 表需补 worker 类型 |
| 地理坐标 / 地形 / 影像 / 3D Tiles | 需自建投影与配准；一期纯空场景可把工程平面坐标局部平移缩放，高程作 Z | 原生地理坐标系、地形 / 影像 / 3D Tiles 生态成熟 |
| 几何交互（剖切、净距、拾取、符号化） | 轻量可控，自定义管线网格 / 线条 / 井体符号灵活 | 能力强但偏重，管线定制符号需额外适配 |
| 离线打包 | 友好：拷贝核心模块 + 所需 addons 到 `public/vendor/` | 可离线，但资源目录大、配置项多 |
| 开源许可 | MIT | Apache-2.0（ion 托管为可选付费，一期不使用） |

**推荐结论（一期）：Three.js。**

理由：一期为纯管线空场景，不使用地形、影像与 3D Tiles，Cesium 的地理 / 实景生态优势无法发挥，却需承担 76.5 MB 解包与整套 Workers/Assets 静态目录；Three 生产核心在 1 MB 量级，几何剖切、净距拾取、管线与井体符号化可控性更好，适配 sandbox 渲染进程。普查成果为工程平面坐标，场景内做局部原点平移与缩放即可，不需要 Web Mercator 投影。

**预留二期**：若后续叠加地形 DEM、影像底图或倾斜摄影 / BIM 实景三维，再评估引入 CesiumJS 或双引擎并存；当前数据模型与接口按「可替换渲染层」设计，场景渲染封装在独立前端模块内，不与业务数据耦合。

### 4.2 前后端职责划分

| 职责 | 归属 | 说明 |
| --- | --- | --- |
| 数据入库、字段映射、拓扑构建、持久化 | 后端（Node + Python 桥） | 落 SQLite，原始文件留 `data/files` 溯源 |
| 拓扑图算法（连通、爆管追溯、最短路径、流向） | 后端 | 由管点-管线构建邻接图，结果返回要素 id 集合 |
| 几何批量计算（净距、碰撞、覆土、剖面、缓冲、土方） | 后端 Python 桥（shapely / numpy） | 批量结果落库或返回前端；前端交互拾取传参 |
| 场景渲染、拾取高亮、剖切交互、剖面 / 曲线绘制 | 前端 Three.js | 只持有渲染态与选中态，业务数据经接口取 |
| 统计聚合 | 后端出数，前端 echarts 展示 | 不在前端造数 |

### 4.3 持久化与权限

- 新增表与 CRUD 遵循 `db.mjs` 既有范式；服务端持久化只走「改内存 → `persistPersistentState()` → `logAudit()`」，不绕过 API 直写 sqlite。
- 权限：一期复用现有 `datacenter` 守卫组；路由键在 `server.mjs` 守卫表同步登记。二期按需要拆分独立 `pipeline` 角色。
- 审计：入库、属性编辑、删除 / 卸载类操作必须记录引用者与数据保留情况（对齐开发规范 2.3）。

## 7. 前端接入方案

- **导航注册**：企业工作台分组新增 `pipeline`；`groups`（app.js 约 659 行）、图标映射（约 2370 行）、模块标签映射（约 13125 / 16280 行）同步登记；render 主分发（约 3282 行段）新增 `if (state.view === 'pipeline') return renderPipeline(view)`。
- **前端状态**：`state.pipeline` 集中管理当前数据集、选中要素、图层显隐、分析结果、面板开合；函数声明 + 显式依赖，不在渲染路径写隐式全局状态。
- **场景布局**：左侧图层树 / 条件查询，中部 Three 视口，右侧属性 / 分析结果面板；底部属性表 / 统计页签。风格沿用中枢黑白灰简约体系，不另起配色。
- **渲染封装**：`pipeline-scene` 独立模块负责场景初始化、管线 / 井体符号、拾取高亮、剖切与视角；业务数据经接口获取，切换数据集 / 清理视口时正确释放 GPU 资源。
- **版本号**：改动前端后递增 `index.html` 的 `app.js?v=` 与相关 css 版本号。

## 8. GIS 桥扩展建议

- `gis-bridge.py` 新增管网子命令（与现有 `inspect/export/convert` 同白名单机制）：
  - `inspect-pipe`：读取点表 / 线表，保留 Z 高程，输出字段清单、要素计数、坐标范围与基础检查结果。
  - `build-topology`：按起终点号构建邻接关系，输出悬挂 / 孤立 / 重复等问题。
  - `analyze-*`：净距、碰撞、覆土、剖面、缓冲等几何计算。
- 读取参数去除管网数据的 `force_2d=True`；二维预览与三维场景共用同一套解析后的结构化数据。
- Python 侧只做解析与几何 / 图计算，不落业务库；落库由 Node 侧按 `db.mjs` 范式完成。

## 9. 分期路线图

### 一期 P0（数据入库 + 三维可视 + 查询）

1. 数据表与 CRUD、数据集导入接边（字段映射、判重、基础校验）。
2. Three 场景搭建：局部坐标配准、管段按类型 / 管径符号化、管点符号、图层显隐、视角交互、拾取高亮。
3. 查询定位：图查属性、条件 / 范围查询、属性表联动。
4. 基础统计：分类长度 / 数量统计 + echarts 图表。

### 一期 P1（几何分析）

5. 横 / 纵断面、水平 / 垂直净距、碰撞检测、覆土埋深分级、缓冲区分析、距离 / 长度量算。
6. 地表参考面开关、半透明地表、竖向剖切视口。

### 二期 P0（拓扑分析 + 数据管理闭环）

7. 连通分析、爆管分析、流向分析、最短路径。
8. 拓扑检查报告（孤立 / 悬挂 / 重复 / 缺坐标高程 / 流向矛盾），问题定位回看。
9. 属性编辑与审计、导出 SHP / GeoJSON / 报表。

### 二期 P1（增强与扩展）

10. 开挖土方量算、场景截图、漫游录制、数据集历史版本与回滚。
11. 地形 / 影像 / 实景三维接口预留与接入评估；与一张图目录挂接。

## 10. 待确认前置项（样本数据到位后核对）

1. **样本成果**：提供一份真实普查 SHP / GDB / GeoJSON（点表 + 线表），核对实际字段名、编码与缺失情况，固化字段映射表。
2. **坐标与高程**：平面坐标系（如 CGCS2000 / 地方独立坐标）、高程基准（1985 国家高程基准等）、坐标单位；是否已有投影信息。
3. **埋深语义**：各类管线埋深是覆土深度还是内底埋深，高程字段是地面高程还是管顶 / 内底高程。
4. **数据量级**：管点 / 管段万级、十万级还是百万级，决定渲染调度（分页 / 分块 / 实例化）与后端索引方案。
5. **管网构成**：本期接入哪几类中类（供水 / 排水 / 燃气 / 热力 / 电力 / 通信…），是否含综合管廊与套管 / 多孔管块。
6. **权限归属**：一期是否直接复用 `datacenter` 权限组，还是单设管网角色。

## 11. 风险与约束

- **离线打包**：Three 核心模块与 addons 须在有网环境预装 / 裁剪后落入 `public/vendor/pipeline/`，随客户端分发；不依赖运行时 CDN。
- **渲染性能**：大数据量需实例化渲染 / 分块加载 / 视口裁剪；要素拾取用 id 映射，不把全量属性塞进场景对象。
- **sandbox 限制**：渲染进程 `nodeIntegration=false`，三维库不得依赖 Node API；worker 如需启用，静态路径与 mime 类型在服务端登记。
- **数据真实性**：未接入真实普查数据前，不内置冒充真实成果的演示管线；界面在无数据集时给出空状态与导入引导，不造假图层。
- **规范合规**：新增路由必须同步守卫表；持久化不绕过 API；删除 / 卸载类操作审计记录引用与数据保留情况。
