# 长期语义记忆 · 实现与验收

## 目标

九规智能中枢在原有 Harness 上下文压缩、会话持久化、会话检索之外，补一套跨会话的长期语义记忆：

- 保存用户稳定的偏好、事实、长期约束和已定决策；
- 按语义召回，只把与当前请求最相关的少量条目注入模型；
- 每条记忆按账号隔离，不跨账号读写；
- 在设置页「长期记忆」中可查看、手动添加、置顶、删除。

## 数据模型

`data/jg.sqlite` 新增 `memories` 表，主要字段：

| 字段 | 说明 |
|---|---|
| `id` | `MEM-…` 唯一 ID |
| `user_id` | 归属账号；所有查询按此过滤 |
| `kind` | `preference` / `fact` / `decision` / `entity` / `task` |
| `scope` / `scope_ref` | `global`、`project`、`conversation` |
| `text` / `normalized` | 原句与归一化文本；`UNIQUE(user_id, normalized)` 去重 |
| `tags` | 标签数组，自动捕获标记 `auto-capture` |
| `confidence` / `pinned` / `status` | 置信度、置顶、`active/archived` |
| `embedding` / `embedding_model` | 向量 JSON 与模型名；无向量时自动降级 |
| `created_at` / `updated_at` / `last_used_at` / `use_count` | 生命周期与使用次数 |

数据库访问集中在 `db.mjs`：`upsertMemory`、`getMemory`、`listMemories`、`listActiveMemories`、`touchMemories`、`archiveMemory`、`deleteMemory`、`setMemoryEmbedding`、`listMemoryEmbeddings`、`memoryCount`。

## 写入

三条真实入口：

1. **自动捕获**：用户话里出现“记住 / 以后都 / 默认 / 我的偏好 / 我不喜欢 / 我们单位 / 我们集团 / 长期…”等稳定表达时，服务端直接把该句写入 `preference`，标签 `auto-capture`，异步补向量，不额外调用模型。
   - 落库前去掉“记住：/记一下，/记着”前缀，只保留事实本身。
   - 工作模式（`resolvedMode=work`）不自动捕获，交给模型调用 `memory_write` 统一改写去重，避免同一条偏好被写两次。
2. **模型工具**：MCP 向模型暴露 `memory_write`、`memory_search`、`memory_list`、`memory_forget`；Chat / Work 核心工具集均已加载。系统提示要求：用户明确说“记住”或表达长期信息时调用 `memory_write`，不要保存一次性任务与敏感信息。
3. **REST**：`GET/POST /api/memories`、`GET /api/memories/search`、`POST /api/memories/delete`，供设置页使用。

写入时调用嵌入接口；接口失败则照常落库、跳过向量，不阻断主流程。

## 召回与注入

- 取该账号最多 600 条 `active` 记忆，按 `scope` 过滤（`global` 全账号；`project` 需匹配 `projectId`；`conversation` 需匹配当前会话）。
- 打分 = 向量余弦相似度 + 字面 n-gram 相似度 + 时效加权；置顶额外加分。
- 阈值：有向量 `0.42`，无向量 `0.18`；最多召回 4 条，注入上限约 760 字符。
- 注入位置：
  - Harness 主路径的 context 数组；
  - 轻量直答（quick-direct）的 system 消息（`includeRules:false`）；
  - 定时任务执行上下文（`includeRules:false`）。
- 注入文本带边界说明：“仅作参考；与用户当前指令冲突时以当前指令为准；不要主动宣称‘我记得’”。

## 账号隔离

- 记忆表按 `user_id` 隔离；列表、检索、归档全部带 `user_id` 条件。
- MCP 进程的 `JG_MCP_ACCOUNT` 是服务级默认账号，不能代表当前对话用户。`/api/ai/invoke` 处理记忆工具时，优先用 `x-jg-conversation` 找到会话的 `userId`，再映射到账号；只有取不到时才回退 MCP 默认账号。
- 数据层实测：以 `test-iso-account` 写入一条记忆后，管理员账号的 `GET /api/memories` 返回 `count=0`，`/api/memories/search?q=隔离测试` 返回 0 条；清理后两个账号均为 0。

## 设置页

设置 → 安全与数据 → 长期记忆：

- 顶部显示条数与向量状态（“语义检索已启用”或“词法匹配（未配置向量接口）”）；
- 列表显示类型、作用域、使用次数、标签、置顶状态；
- 输入框手动添加（默认 `preference/global`）；
- 置顶按钮：写回同一条记忆并 `pinned=true`；
- 删除按钮：归档该条，列表即时刷新；
- 空态文案：还没有长期记忆，可在聊天里说“记住：……”或手动添加。

前端缓存版本：`public/index.html` 使用 `app.js?v=747`。

## 嵌入配置

| 环境变量 | 默认 |
|---|---|
| `JG_MEMORY_EMBEDDING_URL` | `https://dashscope.aliyuncs.com/compatible-mode/v1/embeddings` |
| `JG_MEMORY_EMBEDDING_MODEL` | `text-embedding-v4` |
| `JG_MEMORY_EMBEDDING_KEY` | 依次回退 `DASHSCOPE_API_KEY`、`QWEN_IMAGE_API_KEY` |
| `JG_MEMORY_EMBEDDING_TIMEOUT_MS` | `20000` |
| `JG_MEMORY_DEBUG` | 未设置；设置后输出召回调试日志 |

历史缺向量的记忆按用户每 10 分钟最多回填 10 条，避免每轮都打接口。

## 实测记录（2026-11-17）

- **模型工具写入**：请求“把这条口径记入长期记忆……然后用 memory_write 确认写入成功”，Harness 11.6s、44,576 tokens；模型自行归纳为“所有面积统计统一使用平方米，保留两位小数。”，标签 `面积/统计口径/单位`，`hasEmbedding=true`，向量模型 `text-embedding-v4`。
- **语义召回**：记忆“以后都用一页纸汇报，先结论后数据。”，查询“给领导的汇报材料怎么排版”，score `0.707`，无字面重叠仍命中。
- **轻量直答注入**：新会话“帮我起草一份项目周报的开头，按我平时的汇报偏好来写”，回答开头即“按‘一页纸、先结论后数据’的习惯……”，确认 quick-direct 也吃到记忆。
- **设置页**：空态 `0 条 · 语义检索已启用`；UI 添加后变 `1 条` 并提示“已写入长期记忆”；置顶后显示“偏好 · 已置顶”；删除后回到 `0 条` 并提示“已归档这条记忆”。
- **自动捕获**：说“以后都用一页纸汇报，先结论后数据。”，落库文本已去掉指令前缀，标签 `auto-capture`，`hasEmbedding=true`。
- **隔离**：见上节数据层实测。
- **语法检查**：`db.mjs`、`memory.mjs`、`server.mjs`、`mcp-jg.mjs`、`model.mjs`、`tool-policy.mjs`、`public/app.js` 全部 `node --check` 通过。
- **服务**：`runtime\node.exe server.mjs`，端口 54269，`JG_BACKUP_DISABLED=1`，当前进程 PID 90344，日志 `.run21.out/.err`。
- **当前数据**：`memories` active 条数 **0**；测试记忆全部归档或删除，没有保留伪造偏好。

## 已知边界

- 自动捕获只识别强信号表达，不覆盖“隐含偏好”；后续可选用廉价模型做每轮抽取，但会增加调用成本。
- 前端手动添加默认 `global/preference`；项目级作用域目前由模型工具传参，UI 尚未提供作用域选择。
- 嵌入接口不可用时降级为字面匹配，召回质量会下降；设置页会显示当前状态。
- MCP 记忆工具已改为按会话所有者解析用户；当前环境只有一个真实账号，尚未用第二个真实账号做 MCP 端到端双账号验证。
