# 九规智能中枢 · AI 能力优化落地记录（2026-11-14）

## 本轮目标

把系统从“功能很全的早期 Agent”推进到“可测量、成本可控、可复现”的工程状态。本轮只做高杠杆的三项：

1. 真实 trace 评测基线；
2. 图片预处理、上下文裁剪与模型路由；
3. 工具步数预算。

- `evals/cases.json`：20 条金标用例，覆盖问答、识图、文件、代码、检索、审批、恢复、安全和计划。

## 2. 图片预处理

`server.mjs`：

- `createRequire(import.meta.url)` 从 `dsh-runtime/node_modules/sharp` 懒加载图片处理库。
- `prepareImageForModel()`：长边超过 1568 或文件超过 2MB 时，自动旋转、等比缩到 1568 内、转 JPEG quality 85。
- `imageBlocksForAgent()` 改为 async，调用点改为 `await`；`sharp` 不可用时保留原图，不阻断主链路。

独立验证：

- 输入 `2878×1800`、547,687 字节截图；
- 输出 `1568×981` 附近 JPEG，158,182 字节；
- 体积约降到原来的 29%。

## 3. 上下文裁剪

`server.mjs`：

- `resourcePromptContext()` 按用户问题关键词排序，默认只注入 12 条资源，描述截到 60 字；
- 主上下文标题改为“摘要，最多 12 项；需要更多请调用 drive_search”；
- 项目指令从 4000 字截到 2000；Agent 预设从 8000 截到 4000；分叉上下文从 6000 截到 3000；
- 单个文本附件摘录从 3000 截到 1200；
- `refContextForModel()` 总长超过 8000 时截断并提示读取附件。

这样静态上下文有明确上限，资源目录不再无脑塞满，长附件不会整段进入 prompt。

## 4. 模型路由

`model.mjs`：

- `MODEL_CAPABILITIES`、`modelSupportsImages()`、`classifyTask()`、`routeModel()`；
- 图片请求遇到不支持图片的模型时，回退 `deepseek-flash`；
- 深度思索使用 `deepseek-reasoner`；
- 其他任务保留用户配置模型，分类结果只写入 trace，不强行替用户改模型。

单元验证：

- `deepseek-reasoner + images` → `deepseek-flash`（`image-capability-fallback`）；
- `deepseek-flash + 只回答OK` → `quick` / 保留模型；
- `deepseek-chat + 修改文件` → `work` / 保留模型。

当前 `/api/model/config` 的 `defaultModel` 实际为 `deepseek-chat`；识图请求会自动回退 `deepseek-flash`。如果希望默认就用识图模型，需要在设置页把默认模型切到 `deepseek-flash`。

## 5. 工具步数预算

`harness.mjs` 的 `runAgent()` 新增 `maxToolCalls`：

- 通过包装 `handlers.onEvent` 统计 `tool/call`；
- 超过上限时调用 `session/cancel`；
- 抛出 `STEP_BUDGET_EXCEEDED`，服务端标记本轮失败；
- 服务端按 `taskMode==='chat'` 30、普通任务 60、项目 100、定时任务 60 传入；
- 支持 `JG_MAX_TOOL_CALLS` 环境变量统一覆盖，便于回归和运维降本。

## 6. trace 扩展

`trace.mjs` 的 `buildRunStats()` 新增：

- `taskClass`
- `imageCount`
- `modelReason`
- `replyChars`
- `finishReason`

服务端 trace 顶层新增：

- `requestedModel`
- `modelRoute`
- `reply`
- `images`（只存文件名与 MIME，不存 base64）
- `finishReason`

这样以后可以直接从 trace 判断“是不是识图任务、有没有触发图片回退、回答多长、为什么结束”。

## 13. 接入真实文生图，移除本地合成兜底（2026-11-15）

用户指出“创建图像”生成的是本地合成示意图，且 DeepSeek 聊天模型不具备图像生成能力。处理结果：

- 图像生成与聊天模型解耦：`/api/bootstrap` 新增 `imageGeneration` 能力声明，前端 `imagegenReady()` 只按真实服务状态判断入口，不再要求聊天模型声明 `image`；同时把 `data.mjs` 中 `jg-cloud.image=true` 的虚假声明改为 `false`，避免继续暗示聊天模型自带生图能力。
- 新增服务端 `POST /api/images/generate`：只允许互联网网络和已登录账号；政务网/涉密网拒绝，避免提示词外发。默认 Provider 为 Pollinations `flux`，服务端超时 90 秒，失败返回 502 并附真实原因，不做本地假图兜底。
- 新增 `GET /api/images/file?id=...` 以内联方式返回生成图片；生成文件通过 `putFile` 落到 `data/files`，记录提示词、比例、风格、Provider、模型和 seed，并写审计日志 `image.generate`。
- 中文提示词先做指令前缀清理，再调用当前文本模型翻译成英文图像提示词；翻译不可用时回退清理后的原文。这样“帮我生成一张小猫图”会以“kitten”主体进入生图服务，而不是把整句指令当主体。
- 前端生成按钮改为真实异步请求：生成中显示“正在生成真实图像…”，失败时 toast 真实错误，不再写入 `paintShot()` 结果；“用于会话”按服务端返回的真实 MIME/文件名上传附件。
