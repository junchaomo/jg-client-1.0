# 审批策略与决策审计

## 策略来源

审批不再由产品自定义规则矩阵决定，直接采用 DeepSeek Harness 原生权限预设：

| 产品审批方式 | DSH 权限预设 | 沙箱 | 审批行为 |
|---|---|---|---|
| 请求批准（manual） | `read-only` | 只读 | 需要写入或执行时由 DSH 发起 `approval/request`，产品弹人工确认 |
| 帮我批准（auto） | `workspace-write` | 工作区可写 | 工作区内读写、测试、构建直接执行；越界、外部写入、权限升级才发起 `approval/request` |

DSH 的 `workspace-write` 边界是当前会话工作目录（`session.header.cwd`）。Auto 模式下，工作区内的普通操作不会进入产品审批；能进入产品审批的，都是 DSH 沙箱判断需要升级的动作。因此产品侧不再做“哪些命令可以自动放行”的白名单判断。

## 越权决策归属

审批链路的固定原则：**系统只负责发现越权并生成审批卡，不替用户做 allow/deny 决定。**

- 工作模式：DSH 发起 `approval/request` 后，产品创建待审批卡，由用户选择“仅本次允许”或“拒绝”。
- 对话模式：默认仍使用 `read-only` 沙箱；需要写入或执行时，不再静默返回 `rejected`，而是发审批卡，由用户逐次授权，批准仅本次有效。
- Auto 模式：项目会话直接按工作模式执行；若仍被路由为对话并触发审批，同样发审批卡，不自动拒绝。
- 外部副作用（发消息、建待办、上传等）永远进入审批卡，不在 Auto 下自动放行。
- 无人值守的定时任务没有实时审批人，因此在**创建任务时**必须声明权限范围：`read-only`（只查询）或 `workspace-write`（仅任务目录内读写/构建）。运行时只执行该范围，超出范围立即停止并记录 `scheduled-read-only-scope` / `scheduled-scope-exceeded`，不会自动扩权，也不会假装获得用户授权。

`chat-mode-no-escalation` 与 `dsh-scheduled-escalation-unavailable` 不再作为新的运行时拒绝路径；保留这些常量仅用于兼容历史决策记录。

## 操作类型与风险元数据

`approval-rules.mjs` 只负责审批卡展示和审计落库，不决定 allow/deny。操作类型：

`read` / `write` / `edit` / `delete` / `move` / `execute` / `external-write` / `unknown`

风险元数据用于展示和事后审计：

| 操作 | 风险 |
|---|---|
| `read` | low |
| `write` / `edit` / `unknown` | medium |
| `delete` / `move` / `execute` / `external-write` | high |

## 决策落库

SQLite 的 `approval_decisions` 表保留：

| 字段 | 含义 |
|---|---|
| `decision_id` | 决策唯一 ID |
| `conversation_id` | 会话 ID |
| `call_id` | 工具调用 ID |
| `tool` | 工具名 |
| `operation` | 操作类型 |
| `args_summary` | 参数摘要 |
| `decision` | `pending` / `allowed` / `rejected` / `denied` / `cancelled` / `expired` |
| `rule` | 命中策略：`dsh-workspace-write-escalation`、`dsh-read-only-approval`、`chat-mode-approval`、`auto-chat-runtime-approval`、`scheduled-read-only-scope`、`scheduled-scope-exceeded`、`external-side-effect` |
| `risk` | `low` / `medium` / `high` |
| `actor` | 发起人 |
| `approver` | 放行人（用户名、`policy:chat-mode`、`system-scheduled`、`system-timeout` 等） |
| `net` | 网络域 |
| `time` | ISO 时间 |
| `created_at` / `decided_at` | 毫秒时间戳 |

查询接口：`GET /api/approval-decisions?limit=50`（仅管理角色）。

说明：Auto 模式下工作区内被 DSH 沙箱直接放行的操作不会产生 `approval/request`，因此不会写入 `approval_decisions`；表中记录的是需要产品审批的升级请求及其结果。
